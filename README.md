# Maimemo Companion

与墨墨并排运行的 macOS 伴学侧栏。当前已加入按词生成记忆卡、本地反馈和记法版本。

## 最短运行方式

本机开发构建需要登录钥匙串中的代码签名身份 `Maimemo Companion Local Development`。它是仅供本机测试的自签名证书，不是用于对外分发的 Apple Developer ID；压缩包也仅供这台 Mac 验证。其他开发者可用 `MAIMEMO_SIGNING_IDENTITY` 指定自己的代码签名身份。构建脚本先签名并严格验签，成功后才替换现有 `.app`；不会再静默使用每次都会改变代码身份的临时签名。此机的 Swift 命令行工具还需使用项目内缓存和已有的 macOS 26 SDK，脚本已处理。

先确认 `/Applications/Maimemo.app` 已打开，然后在项目根目录执行：

```sh
./scripts/build-app.sh
open "build/Maimemo Companion.app"
```

首次运行若显示“需要辅助功能权限”（入口在右上角“设置”中）：

1. 在设置页点击“请求授权”或“打开设置”。
2. 在“系统设置 → 隐私与安全性 → 辅助功能”中打开 `Maimemo Companion`。
3. 重新启动侧栏应用。

也可以解压发布的 `.zip` 后直接打开应用。辅助功能授权同时依赖应用路径和代码签名身份；仅保留路径不足以让重新签名的版本继承旧授权。
从旧临时签名版首次换到 0.2.2 时，需要清除旧授权记录并为新签名版授权一次；后续使用同一证书构建，不应再因代码哈希变化而丢失授权。

命令行只读探针：

```sh
./scripts/run-probe.sh --dump
./scripts/run-probe.sh --watch --dump
```

探针会打印墨墨是否运行、当前进程是否有辅助功能权限、读取节点数、最佳单词候选及少量调试候选。它不点击、不写入墨墨、不读剪贴板、不截图。

## 运行边界

墨墨当前词仍通过 macOS 辅助功能只读获取；无需墨墨 API。每切换到一个词，主页只显示英文单词与“给我线索”按钮，先让你在墨墨里自行回忆和判断。点击按钮只揭示本地已有卡片，不会调用模型；没有缓存时，必须再主动点击“生成一条线索”才发起请求。模型尚无预置地址或密钥：随时从主页右上角进入“设置”，填写 OpenAI 兼容的完整聊天补全接口地址、模型名称和 API Key。地址与模型名称保存在本机偏好设置，Key 只保存在 macOS 钥匙串；仓库不包含任何凭证。请求生成时，当前词和你填写的卡点会发送到该模型接口。

0.2.4 的默认侧栏只保留单词和一次揭示动作。首次揭示只展示核心关系和一个语境；“换个说法”逐次显示一条画面或联想，“深入理解”才展开其他义项、迁移新句、反馈和重做记法。多种候选仍由记忆模块保存，但不同时占据侧栏。应用启动时只在后台检查钥匙串里是否有 Key，不读取密钥内容；真正生成时才在后台取用。

0.2.5 起，在墨墨的非全屏窗口右侧空间足够时，侧栏会紧贴其右边缘，并随窗口移动、缩放而调整位置、高度和可用宽度。两者可见的顶边和底边对齐；右侧空间不足以容纳最小侧栏（包括全屏）时，不再执行贴边重排，也不会为了挤入侧栏而移动墨墨。

0.2.3 起，辅助功能树在后台扫描，主界面不再等待另一个应用的响应；重叠扫描会跳过，主页也只在词或连接状态变化时刷新。若墨墨暂时只返回不完整的辅助功能树，主页会把上次可靠结果标为“最近捕获的单词”，而不是声称刚刚实时读取。权限与连接诊断统一在设置页。

已经生成的卡片、当前义项的反馈和记法版本存在本机 `~/Library/Application Support/MaimemoCompanion/memory.json`；重新遇到同词时仍先隐藏，只有主动点击“给我线索”才显示缓存。当前不接墨墨开放 API、不做 OCR、图像生成或 Codex 插件。完整产品目标与路线见 [PROJECT_BRIEF.md](./PROJECT_BRIEF.md)。

模型没有配置时，实时跟词照常运行，界面会明确显示“模型尚未配置”，不会编造 AI 结果。

记忆模块的本地检查：

```sh
swift run word-memory-check
```
