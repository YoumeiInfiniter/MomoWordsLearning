# 📖 Maimemo Companion

在墨墨背单词旁边，给单词搭一座通往记忆的小桥。

> 先自己想一想，需要时再给一条线索。

Maimemo Companion 是原生 macOS 伴学侧栏，独立运行，通过 Accessibility 只读跟随 Mac 上墨墨背单词的当前词。墨墨继续负责复习安排；Companion 帮你把词形、核心意思和当句用法连起来。

当前版本 **0.5.0**。深色玻璃主题保留，文字与图片拥有同级入口、各自线索和共用解释。验证记录与实际使用边界见 [说明与验收记录](./V3_WORD_LINK.md)。

## 从英文原词找到意思

新生成的每份记法都要求给出“原词中的可识别线索 → 如何联到中文含义 → 下次看到原词怎样回忆”。真实构词、声音、熟词片段或语境可以各走一条路径，不能只换一种中文释义。原词定位、必需解释与图片映射由本机校验；这不能代替词典核验或证明记忆效果。

新请求的流式临时线索也会等待原词联系完整后再显示；未完成或未通过校验的正文不会补成完整卡。已有旧版失败原文仍可按原契约免费本地解析。

“文字记法／图像记法”在单词下方同一级切换，不产生模型或生图请求。图片使用准确英文的字母结构表现含义，画面下方单独解释元素怎样对应原词，再共用核心词义、例句和练习。计划与图片按完整卡片版本保存，后台图片完成不会切走当前文字页面。

旧卡和旧图片保留，不会自动重做。旧卡缺少联系或映射时，可主动点“补齐原词联系 · 可能计费”，只发一次文本请求；准备好后仍需另点“生成插画”才会生图。旧缓存图仍可查看，并明确标示尚未记录映射。

## 先回忆，再看线索

每次切词只显示英文。你主动点开学习区域后，已有卡片直接复用；没有卡片才请求一次文本模型。完整首条线索先作为临时线索显示，完整卡片校验与原子保存成功后才加入本机历史；已有失败返回时先提供本地重新解析入口。

新词采用智能选择：先检查词形变化，再检查可理解的真实构词，再评估熟词切块和局部声音联想，选负担小的一条或简短组合。不会按“长词拆词、短词谐音”硬分，也不会切词就自动生成。

- **词形变化**：保留屏幕拼写，说明原形和语法变化；有歧义时不强行还原。
- **真实构词**：区分派生与复合，说明部件作用、词性和整体实际意思。
- **个人拆分助记**：准确覆盖拼写，剩余字母可没有含义，不冒充词源。
- **声音或混合联想**：只补最有用的声音线索，不冒充标准发音。

语言分析由模型提供，结构校验不代表词典核验。主区域保留一条线索、一句核心意思和一个短语境；“为什么这样拆／相关词”最多补三个常用词，看到词族不等于词族都已掌握。

## 不合适，就换记法

展开“换个记法”，四个按钮各执行一次重做：**词根词缀｜熟词拆分｜拆词＋谐音｜换自然谐音**。

“更多调整”提供识别词形、核心＋词族、核心我不认识、只补这个用法和换真实场景。多分支卡需要先选要补的分支；保持它的词性与 meaningKey，其他旧分支及反馈保留。

原因标签只填入请求，不立即生成；额外补充可留空。每次提交固定捕获原词、所选旧版本、预设、原因标签、原始补充、重点分支与模型设置。明显冲突会提示调整。点击换法不记为“忘记”或一次回忆成绩。

重做期间旧卡仍可阅读，失败保留旧卡，不自动追加模型请求。从旧版本重做会追加到末尾；上一条／下一条和“切回已有版本”只读取本机完整卡片，保留历史选择，不发起文本或图片请求。不会将旧联想与另一版本的分析拼在一起。

## 0.4.1：先恢复已有回答

拆分部件的位置由本机按准确拼写计算，模型只填写部件内容，不再数 start/end。`-hood`、`un-` 等词缀记号及省略的可空字段可以本地规范化；只有部件按顺序完整覆盖原词才会接受，不改写教学正文，不补丢失字母或猜学习内容。事实与个人助记标签仍分别检查。

失败时，将已接收回答和原请求上下文暂存到本机 `failed-memory-responses.json`，最多十份、单份回答不超过 1 MB；不保存 HTTP 头或 API Key。重启后可以先点“重新解析已接收内容 · 不调用模型”。这不会调用文本或图片服务，不覆盖更晚的卡片；未提交的新补充也会保留。明确截断、拒绝或缺少必需正文的结果不会被补成完整卡片。

需要新回答时，可主动点“按上次请求重新生成 · 可能计费”，沿用原词、方法、分支和补充，使用当前模型设置重新提交一次。没有隐藏的模型修复或自动付费重试。0.4.0 没有保存失败原文，因此升级无法补回此前已丢失的完整回答。

## 图片在后台继续

有原词联系和画面映射的新卡可在“图像记法”中主动点“生成插画”。智能文本选择、旧卡补齐、词族展开、切换文字／图片与历史浏览均不会自动生图。

图片任务独立于页面，一次生成一张，其他任务排队。同一词、版本、提示词与服务配置的重复点击共用原任务。切词、收起、开设置或切应用后继续等待、下载和保存；返回原词并主动揭示后看缓存图片。旧版本的图片完成后只关联旧版本。

右上角提供小型任务列表。下载最多尝试两次，都针对同一返回地址；失败可手动继续下载／保存原结果，不重新生成。没有可继续的结果时，“重新生成一张”会明确提醒可能再次计费。取消运行中任务只能停止本地等待，不能保证服务商也取消或没有费用。

关闭侧栏窗口后应用继续运行，Dock 或“显示侧栏”可重新打开；**⌘Q／退出应用**才结束进程。任务状态保存在本机。当前沿用项目已有 MaiziAI v2 同步 URL／base64 接口；公开说明中的异步查询协议尚未核验。退出或崩溃后未取得的结果会标为中断／待确认，不会偷偷重新付费提交；已取得的地址或图片可继续下载／保存。Mac 休眠期间不能保证任务持续执行。

## 开始使用

0.4.2 将生成提交阶段的 HTTP 402 单独标为付款／额度限制，提供账户与图片 Key 设置入口，处理后由你主动再次提交。响应明确提示余额或额度不足时显示相应分类；原因不明时不推断具体账户状态。旧版 402 任务无需重新生成即可看到检查建议。客户端不自动重发；是否扣费需查服务商记录。错误响应只提取已知分类，不保存原文。下载阶段的 402 仍按原结果下载失败处理。

1. 打开墨墨和 Companion，在“系统设置 → 隐私与安全性 → 辅助功能”授权 Companion。
2. 在侧栏设置填写文本模型完整接口地址、模型名和 Key；图片 Key 独立配置。
3. 墨墨使用非全屏窗口，右侧留出空间；侧栏不会挤动墨墨。
4. 看到单词先回忆，再点开；需要调整时选一个快捷按钮，需要图片时主动生成。

文本模型采用 OpenAI 兼容聊天补全与 JSON 输出。DeepSeek 官方接口支持原有思考开关，下次请求生效，不重做缓存或重发进行中的请求。图片服务使用 MaiziAI `gpt-image-2.5`，`1:1`、`1K`、`n=1`。文本与图片均可能产生用量费用，客户端不隐式重复付费生成。

Key 仅保存在原有 macOS 钥匙串服务。卡片、分支反馈、历史、图片和任务记录位于 `~/Library/Application Support/MaimemoCompanion/`，不进入 Git。旧数据兼容读取，首次更新旧文件前先备份；不可读文件停止覆盖。生成会把相应词和学习内容发送到你配置的服务。

本项目不是墨墨官方插件，不读取账号、不调用墨墨官方 API、不注入或控制墨墨。当前词识别依赖其辅助功能树；AI 分析和图片仍需自行判断。本轮没有跨项目导出、云同步、自由聊天或其他背词软件适配。

## 从源码构建与检查

需要 macOS 13+、Swift 6 命令行工具及你自己的稳定代码签名身份。仓库不含证书，不提供跨 Mac 的通用签名安装包。

```sh
MAIMEMO_SIGNING_IDENTITY="你的代码签名身份" ./scripts/build-app.sh
open "build/Maimemo Companion.app"
```

离线检查不使用真实 Key、不连接模型服务：

```sh
./Tests/check-word-memory.sh
./Tests/check-companion-lifecycle.sh
```

调试构建可运行 `MaimemoCompanion --offline-preview` 查看隔离的样例页面；发行构建不包含测试入口。当前本机仅有 Command Line Tools，没有 XCTest，生命周期回归采用调试应用内的离线检查入口。

源码：`MaimemoCompanionApp` 管理侧栏；`MaimemoAXCore` 只读取词；`WordMemoryCore` 管理契约、历史与后台队列；`WordMemoryCheck` 提供离线 HTTP／SSE、存储与队列回归。历史技术说明见 [V2](./V2_WORD_LINK.md)、[读取层验证](./VALIDATION.md) 和 [早期模型验证](./MEMORY_VALIDATION.md)。
